Lock the document once, one key per person

The file is encrypted a single time. The file key is then wrapped separately for each recipient's public key, so adding a reader means adding one wrapped key.

2

Each recipient opens it on their own device

Opening produces a copy carrying a hidden mark unique to that person and that open, and a signed record of the event is added to the ledger.

Every copy reads the same on screen. Only the hidden bytes differ:

A copy leaks. Trace it.

Browser build uses Web Crypto as stand-ins: AES-256-GCM for the file, ECDH P-256 key wrapping (HPKE-style) and ECDSA P-256 signatures. The full build swaps these for ML-KEM-768 and ML-DSA-65 (NIST FIPS 203 and 204, via liboqs) with the same flow.
